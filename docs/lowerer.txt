FillLoop: Register Identity Soundness
The fast path is gated on SSA register identity, not static analysis.
An IndexAssign's key register must be the guard's phi register, and the table
register must have been reserved. Any rebind of i or t between header and store
mints a different register and the store silently takes the checked path.
Bump-before-store ('i = i + 1; t[i] = v'), body-local tables, aliases —
all are non-events. The register identity gate carries the soundness.

LoopCtx.nested_fills — Nested fill stores: `(base_table_name, child_reserve_bound_reg)`.
For `t[i][j] = v` inside a loop guarded by `j < N`, `base` is `"t"`
and `reserve_bound` is the pre-lowered `N`.  The lowerer emits
`TableReserve(t[i], N)` right before each `IndexAssign` to the child.
